# godot_chess

Roguelike chess, ported from the TypeScript/Electron prototype to Godot 4.7 (.NET). See [docs/PORT_PLAN.md](docs/PORT_PLAN.md) for the plan and the reasons behind the redesign.

## Layout

| Path | What |
|---|---|
| `src/RogueChess.Engine/` | Rules engine: state, moves, turn resolution, content, AI. Pure C#, **no Godot reference**. |
| `tests/RogueChess.Engine.Tests/` | xUnit tests for the engine. |
| `src/RogueChess.Runs/` | Pure C# run state, encounter handlers, deterministic commands/replay, snapshots and persistence. |
| `tests/RogueChess.Runs.Tests/` | Run/replay, undo, inventory extension, and persistence tests. |
| `run/` | Run host, placeholder overworld, generic battle view, and fixture configuration. |
| `inn/` | The bartender encounter, backed by the run session. |
| `menu/` | Real-time Victorian alley with a 3D, lamplit menu sign and display settings. |
| `sandbox/` | Interactive debug sandbox: load scenarios, play both sides, edit positions, read the resolution trace. |
| `maps/` | `sandbox/` scenarios (generated by `tools/make_scenarios.py`) and `legacy/` maps from the TypeScript prototype. |
| `docs/` | [Plan](docs/PORT_PLAN.md), [resolution rules](docs/RESOLUTION_RULES.md), [content guide](docs/CONTENT_GUIDE.md). |

## Requirements

- Godot **4.7.2 .NET** (the `mono` build). The standard build can't run C# scripts.
- .NET SDK 8 or newer.

## Commands

```bash
dotnet test tests/RogueChess.Engine.Tests/RogueChess.Engine.Tests.csproj
dotnet test tests/RogueChess.Runs.Tests/RogueChess.Runs.Tests.csproj
```

```bash
dotnet build GodotChess.csproj
```

Open the project in Godot .NET and press F5. **Play → New run** opens the placeholder overworld. Move like a king; enter **The inn at c2** to play the bartender, or the **street battle at e4** for a seeded 6x6 encounter. The inn keeps its entrance sequence; the reduced-motion setting skips it.

**Undo move** rewinds your move and the enemy reply while preserving the command trace. Undo is free in this fixture; `IBattleUndoPolicy` supplies future costs. **Concede and leave** (or Esc in the inn) records a resignation and returns to the map. Completing the fixture encounters ends the run; no permanent progression or inventory carryover rules are defined yet.

The default save policy is on return to the overworld, plus run start/end and explicit saves. **Run tools** switches to saving after every command, exports/imports versioned JSON traces, and opens a read-only replay inspector with step/verify controls. Save-policy preferences persist separately from simulation. **Continue saved run** restores the latest save, including active battles and undo history. Saves live in Godot's `user://runs/current.json`, with a `.previous` recovery generation.

For a fixed seed, run `run/Run.tscn` or the main scene with `-- --run-seed=42`. `experiments/gameplay/RunPreview.tscn` skips encounter intros and uses a separate preview save. `experiments/gameplay/VerifyRunFlow.tscn` is an automated integration smoke using its own verification save; it exercises world entry, bartender play/AI, undo, save/load, replay, return, and generic battle entry. It prints `[RunFlow] PASS` and exits on success.

To open the sandbox directly, run `sandbox/Sandbox.tscn` with F6. Existing `--scenario`, `--encounter`, `--seed`, `--white`, and `--black` arguments still route to the sandbox. Each sandbox turn's resolution trace is printed as `[Sandbox] ...`.

The sandbox plays on the wooden 3D board. Left-click to select/move, right-drag to orbit,
and scroll to zoom. Modular piece assemblies are configured in `assets/pieces/visual_catalog.json`;
see [gameplay visuals](docs/CONTENT_GUIDE.md#gameplay-visuals) for mappings and missing-art fallbacks.

For reference-image model generation, the [local asset harness](tools/asset_harness/README.md)
connects portable ComfyUI/TRELLIS.2 to Blender cleanup, mesh validation, quad remeshing and optional rigging.

Regenerate the sandbox scenarios after editing `tools/make_scenarios.py`:

```bash
python tools/make_scenarios.py
```

## Ziva

The Ziva editor add-on is installed per machine into `addons/ziva_agent/` (gitignored, not redistributable). Copy it from another project or install it from ziva.sh.

AI opponents (profiles, per-level injection, tuning): [docs/AI.md](docs/AI.md).

Battles are meant to be short, on small boards (6x6). The sandbox's Encounters row generates the prototype's roguelike battles from `encounters/prototype.json`; see the design direction in [docs/PORT_PLAN.md](docs/PORT_PLAN.md).

The [roguelike run architecture](docs/RUN_ARCHITECTURE.md) describes the implemented foundation, extension contracts, and deferred gameplay systems. The current encounter layout and parameters live in [run/prototype.json](run/prototype.json).
